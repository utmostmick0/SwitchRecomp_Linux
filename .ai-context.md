## Diagnostic rules

- Preserve boundaries between guest virtual addresses, HLE IPC objects, and host graphics resources. Validate mapped guest ranges/permissions; addresses below the heap base are not automatically invalid.
- A svcBreak is a guest-requested stop, not proof of a particular C++ exception. Decode the actual message/result and verify symbol boundaries before assigning a cause. Belmont's previous apparent RTTI/array failure was a clock_gettime system_error.
- Zero GPU submissions/draws means presentation fixes alone cannot establish progress. Inspect guest thread waits, event production, and HLE response layouts first.
- Preserve command-specific IPC sizes and meanings. nvhost event ioctls are not capability structures; renderer getters are not arbitrary voice/effect counters. Use registered sessions/domain objects, not hardcoded handles.
- Synchronization completion must follow the work and output publication it represents. Do not fabricate syncpoint completion during a wait. Sleeps/yields must not unlock a mutex that is not held.
- Empty VI presentation crops may select the full buffer; empty guest drawing scissors can be intentional.
- A shader sampler declaration, coordinate arity, bound texture target, and shader-cache variant must agree.
- Keep logs, saves, extracted game data, generated game code, and rollback executables intact during routine cleanup. Avoid broad indexing of packed assets and captures; inspect specific requested evidence.
